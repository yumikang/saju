## Project Overview

**Name**: 사주 기반 작명 플랫폼 (Saju-based Naming Platform)
**Purpose**: Korean naming service platform combining Saju (사주팔자) fortune-telling with algorithmic analysis

### Core Features
- 알고리즘 기반 작명 시스템 (순수 알고리즘, OpenAI 제거됨)
- Saju (Korean fortune-telling) analysis system
- Real-time naming process with WebSocket (Socket.IO)
- Redis-based queue management
- Mobile-optimized battery management
- Payment integration (TossPayments)
- Multi-provider OAuth authentication (Google, Kakao, Naver)

## Key Features & Systems

### 1. 알고리즘 기반 작명 시스템 (Algorithm-Based Naming)
- **Location**: `app/lib/naming/pipeline.ts`, `app/routes/api.naming.freemium.ts`, `app/socket/handlers/naming.handler.ts`
- **Architecture**: 순수 알고리즘 기반 (OpenAI 제거됨 - 성능 문제로 인해)
- **Performance**: 평균 2-3초 (이전 OpenAI 방식 대비 10배 이상 빠름)

#### 작명 알고리즘 프로세스 (6단계)
1. **사주 분석** (20%) - 사주팔자 계산 및 천간지지 분석
2. **오행 계산** (15%) - 목화토금수 개수 파악 및 균형 분석
3. **용신 결정** (15%) - 용신(유익한 오행) 자동 계산 (복잡한 분석기는 성능상 비활성화)
4. **한자 추천** (25%) - DB 기반 한자 추천 알고리즘 (오행, 성별, 인기도, 부모 가치 필터링)
5. **이름 조합** (15%) - 추천 한자로 최적 조합 생성 및 점수 계산
6. **최종 검증** (10%) - 상위 10개 선별 및 DB 저장

#### 한자 추천 알고리즘
- **필터링 조건**:
  - 부족한 오행 우선 선택
  - 성별에 맞는 한자 (gender preference)
  - 인기도 50점 이상 (popularityScore >= 50)
  - 부모 가치관 매칭 (namingTags)
  - 불용 한자 완전 제외 (taboo characters filtered)
- **점수 계산**:
  - 오행 균형 (30%): 부족한 오행 보충 점수
  - 의미 점수 (30%): 부모 가치 매칭 + 한자 길흉
  - 음향 점수 (20%): 발음 난이도 + 음의 조화
  - 획수 점수 (20%): 81수리 길흉 판단

#### 성능 최적화 전략
- **YongsinAnalyzer 비활성화**: 복잡한 용신 분석 대신 단순 알고리즘 사용
- **OpenAI 제거**: API 호출 제거로 응답 시간 10배 개선 (30초 → 3초)
- **DB 인덱싱**: Element, gender, popularityScore 인덱스 최적화
- **캐싱**: Redis 기반 한자 데이터 캐싱

#### 실시간 진행 추적

- **이벤트**: `naming:progress` (진행률, 현재 단계, 남은 시간)
- **취소 기능**: `naming:cancel` 이벤트로 중단 가능

### 3. Real-time Communication
- **Architecture**: Client (Zustand + Socket.IO) ↔ Socket.IO Server (3001) ↔ Redis ↔ Naming Handler
- **Namespaces**: `/naming` (name generation), `/queue` (queue management)
- **Features**: Progress updates, queue status, real-time results
- **Socket Events**:
  - **Client → Server**: `naming:start`, `naming:cancel`, `queue:join`
  - **Server → Client**: `naming:progress`, `naming:complete`, `naming:error`, `queue:status`

### 4. Queue Management
- **System**: Redis-based FIFO queue with priority support
- **Capacity**: 5 concurrent requests (configurable: `QUEUE_PROCESSING_CAPACITY`)
- **Avg Processing**: 30 seconds per request (`QUEUE_AVG_PROCESSING_TIME`)
- **Location**: `app/socket/queue/`
- **Features**: Fair ordering, priority queue for premium users, automatic cleanup (1 hour)

### 5. Mobile Optimization
- **Battery API**: Adaptive polling based on battery status
- **Modes**: 충전중 (charging), 일반 (normal >20%), 저전력 (low ≤20%), 긴급 (critical ≤10%)
- **Features**: Offline queuing, page visibility detection
- **Location**: `app/hooks/useBatteryOptimization.ts`

### 6. Authentication
- **Providers**: Google, Kakao, Naver (Multi-provider OAuth)
- **System**: Remix Auth v3.7.0 with OAuth2
- **Features**: Account linking, admin authentication, session management
- **Location**: `app/routes/auth.*`, `app/utils/auth.server.ts`, `app/utils/session.server.ts`

### 7. Payment Integration
- **Provider**: TossPayments (Korean payment gateway)
- **Models**: Freemium with premium upgrade
- **Features**: Payment verification, webhook handling, transaction history
- **Location**: `app/routes/account.payments.*`, `pay/` directory

### 8. Admin System
- **Features**: User management, metrics dashboard, audit logs, account linking
- **Location**: `app/routes/admin.*`
- **Auth**: Separate admin authentication system (`app/utils/admin-config.server.ts`)
- **Pages**: Users, Metrics, Audit, Account Link, Dev Login
